# 超星填空题自动回填方案

> 状态：step1（题型识别）+ step2（双路径注入引擎）已全部落地；多空数组答案缺口已修复。

## 一、背景与关键约束

- **学习通禁止复制粘贴**：实测超星页面拦截 `paste` 事件 / 右键菜单 / `onpaste="return false"`。
- **结论**：禁止粘贴 **拦不住** 本方案的回填——因为回填走**程序化写入**（直接改原生 `.value` + 派发 `input`/`change` 事件），根本不经过剪贴板，粘贴拦截对其无效。
- **真正要处理的坑**：部分超星填空不是 `<input type=text>`，而是 `contenteditable` 富文本编辑器。对 `contenteditable` 直接设 `innerHTML` 会被 Vue 校验器丢弃，必须用 `document.execCommand('insertText')` / `Selection.insertText` 模拟真实输入。

## 二、step1 — 题型识别（填空 / 主观拆分）

旧逻辑把"无序号题"笼统归并。现按输入控件类型拆开：

- **填空题** = 单 `input[type=text]` 或 `input.filldown` / `input[class*="fill"]` / `textarea.answertext` / `textarea[class*="fill"]`，**无选项**。
- **主观题（简答/开放长文）** = 含 `textarea` 且不匹配上述 fill 类选择器。

落点：
- `sites/chaoxing-exam.js`：`fillInputSels`（填空输入选择器，作为题型识别与注入的依据）。
- `takeover/engine/quiz.js`：`_quizDetectQType(qEl, opts, sels)` → `'choice' | 'fill' | 'subjective'`。
  - 填空 → 登记 `_quizFillItems[fp]` + `_quizSkipCounts.fill++`（**蓝灯**，待回填）。
  - 主观 → 维持 `_quizInfoMissing`（**橙灯**，人工队列）。

## 三、step2 — 双路径注入填空引擎

### 1. 答案来源（优先级）
`_quizResolveFillAnswer(stem, fp)`：
1. **题库文本命中（优先）**：`quizBank[stem]` 为字符串（单空）或数组（多空逐空）→ `source: 'bank'`。
2. **AI 文本模式**：仅当 `_quizSource() === 'ai'` 且题目在外发白名单内，调用 `_quizAskAI(stem, [])`（填空无选项 → 空 options），端点回传 `answer` 文本并自动写回 `quizBank`。
3. 否则 → 无答案源，转人工（蓝灯保持）。

> 多空数组：`b instanceof Array` 时返回 `{ text: b }`，由注入器逐空填入。

### 2. 双路径注入（不依赖剪贴板）
`_quizFillInject(qEl, sels, text)` 按加载顺序尝试：
- **路径 A（首选）** `input` / `textarea`：`Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype,'value').set` 改原生值 + 派发 `input`/`change`。
- **路径 B（fallback）** `contenteditable`：`Selection.insertText` / `document.execCommand('insertText')` 模拟真实输入（避开 Vue 校验器）。

多空题：`text` 为数组时逐空填入（`_els[_i]` 对应 `_arr[_i]`）；单字符串则所有空填同值。

### 3. 不自动提交
`_quizFillAnswer` 解出并注入后 **不** 调用 `_quizMaybeSubmit`，而是挂 `_quizPendingSubmit`（二次确认队列），遵循"先回填、后人工确认交卷"的策略——与选择/简答的自动提交解耦，降低误交风险。

### 4. 面板开关（默认关）
- key：`CX_KEYS.QUIZ_FILL_ENABLED`。
- `_quizFillEnabled()` 默认 `false`（未显式置 `'1'` 即不开）——填空回填属高风险动作，需用户面板显式开启。
- `panel-controls.js`：`#__cxQuizFillEnabled` 复选框默认不勾选；开启 toast 提示「填空题自动作答已开启（仅题库/AI 命中，不自动提交）」。

## 四、配套展示

- **信号灯**：`dashboard.js` 新增 `fill` 态，配色青 `#06b6d4`，标签「填空题待回填」；`quiz.js` 状态机 `_quizSyncLights` 暴露 `fill`。
- **重置护栏**：`quizHardReset` 的 `_cnt` 统计已含 `_quizFillItems`；`_quizPruneFill()` 镜像 `_quizReviewItems` 做内存护栏。
- **诊断**：`diagnostics.js` 输出 `填空自动作答: 开(仅题库/AI命中·不自动提交) / 关(填空题留待人工)`；`quizStats` 暴露 `fillCount` 与 skip `fill`。

## 五、本次收口修复

- **多空数组答案误判**：原 `_quizResolveFillAnswer` 仅接受 `typeof b === 'string'`，题库存数组被误判为"非填空答案"返回 null，多空题无法回填。已补 `if (b instanceof Array) return { text: b, ... }`，与 `_quizFillInject` 的数组逐空逻辑对齐。改后 `quiz.js` lint 为 0。

## 六、待验证（实站）

4. 面板开启后仅"题库/AI 命中"才回填，**未点二次确认不交卷**。
