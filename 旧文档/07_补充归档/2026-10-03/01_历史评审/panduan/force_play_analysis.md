# 学习通·强制续播用户脚本（v3.16）详细分析

## 一、整体结构与模块划分

该脚本是一个用于学习通（超星）网课页面的浏览器用户脚本，核心目标是在平台试图暂停、伪暂停（把播放速率改到 0）或重播已结束视频时，强制让"任务点视频"持续播放，同时尊重自动跳课的暂停锁，并能精确跳过广告与插播视频。整个程序包裹在一个立即执行函数内，采用严格模式，按职责可划分为八个逻辑模块。

第一个模块是全局配置与日志。脚本顶部定义了轮询间隔常量，以及通过 DEBUG 开关条件编译出的日志函数。由于日志函数本体根据 DEBUG 是否为真在定义时就已经分支固化，正式发布版本中 DEBUG 为假时它直接是一个空函数，热路径上不产生任何参数收集或拼接开销。

第二个模块是原型级拦截。它分别在 HTMLMediaElement 原型上覆盖了 pause 方法，并重写了 playbackRate 的访问器描述符。这两处是整份脚本防御力的根基，因为平台很多暂停逻辑藏在闭包或打包工具私有函数里直接调用原生方法，只覆盖全局对象或实例方法拦不住。

第三个模块是定向续播白名单。它维护一个 TARGET 状态对象，从页面渲染后挂到顶层窗口的 attachments 数组里抽取任务点视频标识，结合本地桥服务提供的 objectids 共同构建白名单。模块内还负责安装 attachments 的 setter 钩子以便异步到达时即时重建白名单，以及用带边界约束的正则做精确匹配。

第四个模块是本地桥服务集成。它通过 HTTP 与本地爬虫服务通信，拉取当前章节的清单。桥服务有两个作用：一是当当前章节已被标记为完成时整体避让续播，避免重进已学完的章节被重新强播；二是用爬虫侧权威的 objectids 预填白名单，使定向续播不依赖页面 AJAX 渲染时机。

第五个模块是重播加固。它维护一个以视频当前地址和祖先 iframe 签名为键的"已结束集合"，用于识别平台在跳课时"销毁旧视频并以全新元素重建同一已播完视频"的行为，从而把这种重建元素锁死不播。

第六个模块是核心接管逻辑。它包含安全的播放函数、接管视频的主函数、释放接管的函数，以及中和平台全局暂停封装的函数。这里集中了 ended 持久锁、seeking 守卫、伪暂停回拉、缓冲枯竭续播等几乎所有运行时行为。

第七个模块是扫描与发现。它递归遍历文档、Shadow DOM 和同源 iframe 来定位视频元素，并对每个视频调用接管逻辑，同时中和子帧内的全局暂停封装。

第八个模块是生命周期与调度。包含初始安装、每两秒一次的低频全量重扫定时器、合并到下一帧批量处理的 MutationObserver，以及切回标签页时的强制续播。

## 二、核心算法逻辑与关键函数作用

原型 pause 覆盖是第一个关键机制。脚本先备份原生 HTMLMediaElement.prototype.pause 到 NATIVE_PAUSE，再用一个包装函数替换原型方法：当被调用对象的 __cxForcePaused 标志为真（即本脚本已接管该视频）时直接返回，跳过原生暂停；否则透传原生逻辑。由于这是原型方法，任何闭包私有暂停、webpack 私有函数里的 video.pause() 调用都会走这条路径被拦截，而未被接管的广告视频仍可正常暂停。自动跳课的暂停锁则通过原生备份 __np 真正暂停，绕过了拦截。

原型 playbackRate 访问器是第二个关键机制。脚本先取出原生描述符，再用 Object.defineProperty 重新定义 playbackRate，在 setter 中判断：如果视频已被接管、且未被自动跳课锁定、且被赋的速率小于等于 0.01（平台伪暂停的常见手法），则把速率改写为 1x。这覆盖了即使用户或平台通过速率设 0 冻结画面的场景，同时保留用户正常的倍速设置。

定向白名单构建是第三个核心算法。collectAttachmentIds 遍历 window.attachments，从每个任务点的 property 中取出 objectid、mid、id 等标识，并兼容子附件与子列表的递归结构。refreshTargets 把 attachments 的标识与桥服务清单的 objectids 合并成 TARGET.ids，并生成排序后的 key 数组供热路径复用。它引入了一个滞回设计：当 TARGET 已启用但本轮 attachments 暂为空窗时，保持稳定不回退，避免定向与全量模式来回横跳误伤广告；只有从未启用状态才会回退为全量。真实章节切换由任务键集合变化触发，此时才清空已结束集合与正则缓存。

keyRe 边界正则是匹配的精度保障。它对每个白名单标识生成要求前后为非字母数字边界或字符串边界的正则。这种写法既能防止 "123" 误命中 "12345"（因为后者中 123 之后是字母数字 5，边界不成立），又不会像早期某个版本那样把边界收窄到 ".?&#" 等字符而导致漏匹 "lesson_123" 这类用下划线或连字符包裹的合法标识。正则实例被缓存以避免重复编译。

videoBelongsToTask 与 videoIframeSrcsOf 是匹配的具体执行。前者向上收集视频自身的 currentSrc、src，以及所有祖先 iframe 的 src、id、name、data 属性，逐一用边界正则测试是否命中白名单；未命中即视为广告或插播，予以跳过。后者专门收集视频自身 id 及其祖先 iframe 的签名（id、name、title、data-* 属性值），用于重建去重时的指纹，即使视频走 MSE 后 currentSrc 是 blob 地址也能靠 iframe 签名命中任务标识。

ended 持久锁是阻断重播的核心。当视频进入 ended 状态时，接管函数先调用原生备份真正停住，然后把 play 重写为永远返回已完成 Promise 的函数，置持久标志 __cxEndedLock，把当前地址和祖先 iframe 签名登记进已结束集合，并把 currentTime 拉到视频末尾，同时挂载一个 seeking 守卫：一旦平台把播放位置改小，立即拉回末尾。这个锁在后续每次重扫时持续维持，不再恢复原生 play，从而堵住平台通过 video.play() 或重建元素重播的多种手法。

重建去重是 ended 锁的延伸。isRebuildFinished 检查新视频的地址或 iframe 签名是否命中已结束集合，命中则视为同一已播完任务点的整元素重建，锁死不播，但不影响新一课的视频。

safePlay 是安全续播封装。它先记录视频原始静音状态，尝试原生 play；若被浏览器自动播放策略拒绝，则静音重试一次，并在 playing 事件（用 once 标志注册，避免监听器泄漏）真正触发后再恢复用户预期音量，避免提前取消静音造成爆音。

桥避让 skipResume 是协同保护。当桥清单标记当前章节已完成且无未完成任务点时，脚本整体跳过接管，并恢复被覆盖视频的原生 pause，把暂停控制权交还用户与平台。

## 三、输入输出格式说明

输入方面，脚本主要消费四类来源。其一是页面运行期挂到顶层窗口的 attachments 数组，结构为任务点对象数组，每项含 property 子对象携带 objectid、mid、id、type 等字段。其二是本地桥服务的 HTTP 接口，脚本向 base 地址下的 /playlist/课程号 发起请求，期望返回含 chapters 数组的 JSON，每个章节项有 knowledgeId、completed、unfinishedCount、objectids 等字段；同时向 /ping 探活。其三是 URL 查询参数，包括 courseId、chapterId 或 knowledgeId（兼容置于 hash 的新模板路由），以及可选的 cxbridge 用于配置桥地址。其四是 DOM 中实时存在的 video 元素、video 的 currentSrc/src、祖先 iframe 的 src 与各签名属性，以及 navigator.mediaSession 状态。

输出方面，脚本几乎没有返回值，全部表现为对运行时环境的副作用。它对命中的视频元素改写 pause 为 no-op、改写 play 为 no-op（已结束或重建场景）、把 playbackRate 的低值改写为 1x、把 currentTime 拉到末尾并守卫 seeking，同时劫持 mediaSession 把 pause 动作置空并把播放状态标为 playing。它对 window.attachments 重定义了 setter，对 HTMLMediaElement 原型做了永久改写。debug 开启时还会向控制台输出带前缀的日志。所有这些输出都是浏览器页面内的状态变更，不涉及文件或网络回写（桥服务是只读拉取）。

## 四、时间与空间复杂度评估

扫描函数每次执行对文档内所有 video 元素做线性遍历，复杂度为视频数量 N 的线性级别。由于视频容器通常在同一页面内数量有限（个位数到几十），这一开销极低。定向匹配阶段对每个视频遍历其收集的若干 URL 与白名单 key 数组，最坏为 O(N × |URLs| × |keys|)，但白名单 key 通常也只在几十量级，且正则已缓存，实际可忽略。Shadow DOM 扫描被刻意收窄到视频容器子树内，避免了长章节页面在评论区、目录区大规模枚举的开销；ShadowRoot 内部子树较小才做全量枚举。

调度层面，定时器每两秒触发一次全量重扫，属于低频后台任务，对主线程是周期性小负担。MutationObserver 不在每次 DOM 变动时立即处理，而是把新增 video 节点入队并合并到下一帧（优先 requestAnimationFrame，退化用 setTimeout 16 毫秒）批量接管，把高频弹幕、进度条更新的冲击摊平。桥服务的 playlist 与 ping 请求是异步低频网络调用，只在页面加载初期与默认端口不通时触发探测，不进入热路径。

空间占用上，已结束集合 ENDED_SRCS 是持续累积的字典，仅在真实章节切换时由 refreshTargets 清空，因此单章内长时间播放只增长有限条目；正则缓存 _keyReCache 与任务键数同量级，规模很小。整体内存占用恒定且可控，无递增泄漏。

## 五、潜在的边界条件与异常处理机制

脚本对跨域 iframe 做了 try-catch 包裹，读不到父帧或子帧内容时静默跳过，不阻断同源视频处理。对 HTMLMediaElement 原型可能不存在的环境（极旧浏览器或非浏览器宿主）做了存在性判断，避免启动崩溃。桥服务 fetch 在严格 CSP 的 connect-src 限制下可能同步抛异常，脚本在调用处就地捕获或走 promise 的 catch，保证桥不可达时静默回退到原有行为，零新增硬依赖。

直播场景下视频 duration 为 Infinity，脚本在所有涉及 currentTime 赋值和 seeking 复位处都加了 isFinite 守卫，避免向 Infinity 赋值或误把直播流重置到末尾。自动跳课暂停锁 __cxAN_hold 被每一个续播分支检查，确保插播题、答题需要暂停时本脚本无条件避让，不会与 auto-next 脚本打架。桥避让 skipResume 迟到到达时，脚本会调用 restoreNativePause 递归恢复文档及同源 iframe 内视频的原生 pause 实例方法，把控制权交还。

attachments 永不出现（旧版或移动端页）时，桥 objectids 可独立撑起白名单，避免"无米之炊"。attachments 自身已被平台定义为不可重定义的属性时，setter 钩子安装失败，脚本退回两秒轮询兜底。MutationObserver 或 requestAnimationFrame 不可用时退化为 setTimeout。原型 pause 的覆盖在直接赋值因描述符不可写而失败时，回退用 defineProperty 强行遮蔽，再失败则不影响其余逻辑。

## 六、可能存在的优化点与改进建议

桥服务地址默认使用 http 协议访问 127.0.0.1。脚本注释称 127.0.0.1 属于 potentially-trustworthy origin 因此 https 页面可直接 fetch，这一判断并不准确：http://127.0.0.1 并非 HTTPS，在学习通这类 https 页面上发起的 http 主动混合内容请求仍会被浏览器阻止，导致桥的 skipResume 与 objectids 预填在线上环境实际失效，只剩轮询兜底。建议桥服务改监听 https（或 localhost 的 127.0.0.1 在部分浏览器虽免混合内容但仍非标准做法），或让脚本在 https 页面优先尝试 https 桥地址并回退。

重扫定时器里若本轮定向模式零命中会直接关闭 TARGET.enabled，但上一行 refreshTargets 刚把它重新打开，下一次轮询又会重新打开。在视频尚未插入的瞬间页面上，这会表现为启用与关闭的轻微振荡。虽然不影响最终命中，但建议在关闭定向时也引入与空窗滞回类似的迟滞，例如连续若干轮零命中才回退，减少白名单状态抖动。

safePlay 每次被调用都会注册一个 playing 监听器（即便用 once 标志，也需等 playing 触发才移除）。在视频始终无法进入 playing（例如自动播放策略彻底禁止且无用户手势）的极端情况下，频繁调用 safePlay 会累积瞬时监听器。可在注册前判断该视频是否已有未触发的恢复监听器，或改用带标志去重的方案。

原型 pause 覆盖在每次定时器轮询时都重新执行一次 installPrototypePauseNeutralize，虽不会形成包装链（每次都直接引用原始 NATIVE_PAUSE 重新赋值），但属于重复无差别操作。可加一个幂等判断，仅在原型未被本脚本标记过时再覆盖，降低每轮微小开销。

scanVideos 在文档级只扫描 #videoBox 与 .ans-attach-ct 子树内的 Shadow 宿主，这一收窄依赖平台容器类名稳定。若平台改版移除这两个类名，Shadow DOM 内的视频将不再被发现，只能靠两秒轮询兜底。建议保留一个轻量的全文档 Shadow 宿主兜底扫描，或把容器选择器做成可配置常量。

跨脚本契约（__cxAN_hold、__np、__cxForcePaused 等）仅靠注释约定，一旦任一协作脚本改名会静默失效。建议在脚本顶部以统一常量集中声明这些契约字段名，并在启动期做一次双边自检日志，降低多脚本协同的维护风险。

最后，脚本整体注释非常详尽，对每一处历史缺陷修复都有来源标注，工程可读性良好；若后续继续迭代，建议把"已修复 X 处"的演进说明收敛进 CHANGELOG，避免在代码注释里堆叠过长版本叙述，保持主逻辑区域清爽。
