# 主控面板 UI 设计方案（force-play v5 设计稿）

> 对象：`ecosystem/chaoxing-force-play.user.js` 悬浮主控面板（源码 `ecosystem/src/chaoxing-force-play/`）
> 约束：单 IIFE、零运行时依赖、单文件构建、Tampermonkey 宿主页面不可控
> 关系：本文是**设计方案**，不改代码；落地按 §10 分阶段执行，沿用重构方案的三重验证（代码行多重集 diff + 语法检查 + Tampermonkey 冒烟）
> 配套可视化设计稿：`docs/ui-design/prototype.html`（本地静态预览）

---

## 1. 现状诊断（为什么需要设计规范）

当前面板（v4.8）功能已很完整：命令系统、副脚本注册、运维仪表盘、Ninja 模式、移动端适配。但作为 UI 存在四个结构性问题：

| # | 问题 | 证据（源码） | 后果 |
|---|------|------------|------|
| 1 | **样式无令牌，硬编码散落** | `ensurePanel` 内约 110 行内联样式字符串拼接；同一灰色出现 `#3a3f4b / #4b5563 / #2a2e37` 三个近似值 | 改一处风格要动几十处；副脚本各写各的色，面板视觉不统一 |
| 2 | **信息架构失衡** | 「高级」tab 同时承载：仪表盘 + 视频信息 + 诊断 + 4 个设置项；「其他」tab 只有 2 个按钮 | 高频操作（速率）藏在低频 tab；tab 间密度悬殊 |
| 3 | **按钮语义无分级** | 同屏出现 4 种按钮：蓝 `#2d6cdf`、灰 `#3a3f4b`、深灰 `#4b5563`、描边 `#1e293b/#3b82f6`，无章可循 | 主操作（暂停/恢复）与三级操作（导出日志）视觉平级 |
| 4 | **反馈渠道分散** | 状态徽章（圆点）、命中率 LED、toast、`__cxPanelState` 文字区、诊断块并存，无级别约定 | 用户不知道"这个反馈该不该管"；排错时不知道看哪 |

> 设计目标不是"换皮美化"，而是：**把视觉收口为令牌、把信息分层、把反馈分级**，同时为副脚本提供统一的 UI 接入规范。

---

## 2. 设计目标与原则

**目标（按优先级）**
1. **一眼知状态**：不展开面板也知道脚本是否在工作（对抗类脚本的第一诉求）。
2. **高频操作 ≤2 次点击**：暂停/恢复、速率、自动下一课是日操；黑匣子导出是月操，分层收纳。
3. **副脚本视觉同构**：addon 注册进面板后像原生组件，不像是"贴上去的"。

**原则**
- **务实优先**：这是工具面板不是产品页，克制装饰，信息密度高于留白美学。
- **令牌先行**：任何颜色/字号/间距必须来自令牌表，禁止新硬编码。
- **零依赖守序**：不改单文件构建、不引入框架，组件用纯 DOM + 令牌常量实现。
- **行为零回归**：UI 重构不动核心逻辑，沿用 P0–P4 已建立的 `Store.emit/onEv` 事件总线。

## 3. 设计令牌（Design Tokens）

所有令牌收口到 `meta-config/config.js` 的 `STYLES` 对象（单一事实源），组件只引用令牌。

### 3.1 色板（深色主题，语义命名）

| 令牌 | 值 | 用途 | 现状对照 |
|------|----|------|----------|
| `--bg` | `rgba(20,22,28,.96)` | 面板底色 | 沿用 `PANEL_BOX` |
| `--surface` | `#1a1d24` | 输入框/下拉/嵌套卡底色 | 沿用命令输入框 |
| `--surface-2` | `rgba(0,0,0,.25)` | 仪表盘格、信息块 | 沿用 |
| `--border` | `#3a3f4b` | 统一描边/分隔线 | **收敛**：`#2a2e37` 归并到此 |
| `--text` | `#e8e8e8` | 主文字 | 沿用 |
| `--text-2` | `#9aa0a8` | 次级文字 | 沿用 |
| `--text-3` | `#6b7280` | 弱化文字/占位 | 沿用 |
| `--primary` | `#2d6cdf` | 主按钮/激活态/链接 | 沿用 |
| `--success` | `#22c55e` | 运行中/成功率 | 沿用 |
| `--warning` | `#f59e0b` | 收藏/警告 | 沿用 |
| `--danger` | `#ef4444` | **新增**：破坏性操作（清空日志/重置配置） | 现状缺位 |
| `--idle` | `#4b5563` | 未激活/禁用态 | **收敛**：仅作状态色，不再作按钮色 |

### 3.2 字阶 / 间距 / 圆角 / 层级

| 类别 | 令牌阶梯 | 说明 |
|------|----------|------|
| 字号 | `9 / 11 / 12 / 13 / 14px` | 9=仪表盘标签，11=辅助，12=正文，13=主按钮，14=标题；**禁止** 10px（现状散见，归并到 9 或 11） |
| 间距 | `4 / 6 / 8 / 12px`（4 的倍数） | 组件内 4-6，组件间 8，区块间 12 |
| 圆角 | `4`（小件）/ `6`（按钮输入）/ `8`（面板） | 三级，禁止其他值 |
| 阴影 | `0 6px 24px rgba(0,0,0,.45)` | 仅面板与浮层下拉使用 |
| z-index | 面板/Toast 恒为 `2147483647`（现状）；下拉相对面板内 `10` | 不变 |

> 落地形式：`STYLES.T = { bg:..., surface:..., ... }` 令牌表 + 现有 `PANEL_BOX` 等复合样式改为引用令牌拼接。**新增 `danger` 是唯一新色值**，其余全是收敛与命名。

## 4. 信息架构（IA）重组

### 4.1 三区模型

```
┌─────────────────────────────────┐
│ A. 常驻状态条（不随 tab 切换）      │  ● 运行徽章 · 标题 · 当前速率 · ×
├─────────────────────────────────┤
│ B. 命令栏（常驻，差异化能力）       │  / 命令输入 + 下拉 + 收藏
├─────────────────────────────────┤
│ C. Tab 内容区（4 tab 重定义）      │
│   [主控] [自动化] [洞察] [系统]    │
└─────────────────────────────────┘
```

A、B 区保持现状（已验证好用），**重构只发生在 C 区的 tab 划分**。

### 4.2 Tab 重定义（现状 → 方案）

| 新 Tab | 定位 | 收纳内容 | 来源（现状位置） |
|--------|------|----------|------------------|
| **主控** | 日操：播放控制 | 暂停/恢复大按钮；视频开关列表（仅播此轨/全部续播/锁定前台） | 现「暂停设置」上半 + 视频列表 |
| **自动化** | 日操：让脚本自己跑 | 自动停止滑块、暂停后自动恢复滑块、循环播放、**播放速率**、副脚本开关（自动下一课等） | 现「暂停设置」下半 + 现「高级」的速率 + 现「副面板」的副脚本区 |
| **洞察** | 周操：看运行状况 | 运维仪表盘（MO队列/命中率/成功率）、视频信息、诊断块、内嵌副面板（进度面板） | 现「高级」上半 + 现「副面板」的副面板区 |
| **系统** | 月操：维护 | 轮询间隔、进度到底释放、单视频模式、Ninja 模式、调试日志、复制诊断、导出黑匣子、快捷键说明 | 现「高级」下半 + 现「其他」全部 |

**关键调整理由**
- **速率从「高级」提到「自动化」**：速率是仅次于暂停的高频操作（证据：命令系统中 `/rate` 是带参命令且支持收藏）。
- **副脚本开关与副面板拆分到两个 tab**：开关是"操作"（自动化），进度面板是"看"（洞察），不再挤在同一 tab。
- **「其他」改名「系统」并收纳所有低频设置**：消除"高级/其他"语义重叠（现状两个 tab 都是"杂项"）。

### 4.3 线框（主控 tab，标准态）

```
● 学习通·主控面板  v5.0        1.5x  ×
┌────────────────────────────────────┐
│ / 输入命令…                         │
└────────────────────────────────────┘
[主控] [自动化] [洞察] [系统]
┌────────────────────────────────────┐
│ ┌────────────────────────────────┐ │
│ │       ⏸ 暂停 / ▶ 恢复          │ │  ← primary 大按钮（一级操作）
│ └────────────────────────────────┘ │
│ 视频开关          [仅播此轨][全部续播]│
│ ┌────────────────────────────────┐ │
│ │★1 ▶ 任务点视频  12:34/45:00    │ │  ← 列表项：序号/状态/标题/进度
│ │ 2 ⏸ 插播        00:30/01:00    │ │
│ └────────────────────────────────┘ │
│ ☐ 锁定前台                          │
└────────────────────────────────────┘
```

## 5. 组件规范

### 5.1 按钮四级制（收敛现状 4 种混乱样式）

| 级别 | 样式 | 用途 | 实例 |
|------|------|------|------|
| **Primary** | `--primary` 底 + 白字，高 36px | 每 tab 唯一一级操作 | 暂停/恢复 |
| **Secondary** | `--border` 底 + `--text` 字，高 28px | 常规操作 | 仅播此轨、全部续播、复制诊断 |
| **Ghost** | 透明底 + `--primary` 描边与字 | 辅助/可逆操作 | 导出日志 |
| **Danger** | `--danger` 描边 + `--danger` 字 | 破坏性操作（需 confirm） | 清空黑匣子（新增） |

> 规则：`--idle`（#4b5563）**不再用作按钮底色**（现状"全部续播"用它，与禁用态混淆），统一归 Secondary。

### 5.2 其余组件

| 组件 | 规范 | 变化 |
|------|------|------|
| 开关 checkbox | 保持原生 checkbox + `--primary` accent-color；标签 12px | 现状不变，仅统一标签间距 6px |
| 滑块 range | 标签行内右侧 `<b>` 实时显值（现状已如此），轨道高 4px | 统一「标签: 值」冒号格式 |
| 状态徽章 | 标题栏 10px 圆点：绿=运行 / 黄=暂停中 / 灰=空闲 / 红=错误 | **语义成文**（现状隐式） |
| Toast | 右下角，分级：info(默认黑) / success(绿边) / warn(黄边) / error(红边) | 新增级别参数 `toast(msg, level)` |
| 卡片 | `--surface-2` 底 + 4px 圆角 + 5px 内边距（仪表盘格现状如此，成文化） | 无 |
| Tab 导航 | 激活 `--primary`，未激活 `--border` 底 | 现状不变 |

### 5.3 副脚本接入规范（addon 视觉同构）

`__cxAddonQueue` 协议不变，新增**约定**（文档化，不强制校验）：
- toggle 型 addon 渲染在「自动化」tab，label 建议 ≤8 字；
- subpanel 型 addon 渲染在「洞察」tab，标题栏折叠态高 32px；
- addon 内需要按钮时，主脚本暴露 `STYLES.BTN_SECONDARY` 等令牌供其引用（`window.__cxUI = STYLES`，**新增导出**），避免副脚本各自配色。

## 6. 交互与反馈规范

### 6.1 反馈分级矩阵（什么操作用什么反馈）

| 操作后果 | 反馈渠道 | 实例 |
|----------|----------|------|
| 即时可逆的小操作 | toast info，1.5s 自动消失 | 暂停成功、速率已设 |
| 状态持续变化 | 常驻 UI 自身更新（徽章/列表/显值），**不弹 toast** | 视频列表状态翻转、滑块值 |
| 影响后续流程 | toast warn + 状态区落一行 | 单视频模式已开 |
| 失败/异常 | toast error + 写入近期错误（P0 的 `_errBuf`） | 命令执行出错 |
| 破坏性操作 | confirm 二次确认 | 清空日志、重置配置 |

> 解决现状"操作反馈全靠 toast 刷屏"的问题：**状态类变化不再发 toast**。

### 6.2 快捷键表（成文，现状隐式）

| 键 | 作用 | 条件 |
|----|------|------|
| `P` | 开关面板 | 非输入框聚焦 |
| `Esc` | 关闭命令下拉 → 再按关闭面板 | 分层关闭 |
| `/` | 聚焦命令栏 | 面板可见时 |
| `↑↓` / `Tab` / `Enter` | 命令选择与补全 | 命令栏聚焦 |

### 6.3 空态与异常态

| 场景 | 表现 |
|------|------|
| 页面无视频 | 视频列表区显示「未检测到视频」（12px `--text-3` 居中），而非空白 |
| 桥离线 | 洞察 tab 诊断块首行显示黄色「桥离线 · DOM 兜底中」，徽章变黄 |
| 副脚本为 0 | 「自动化」tab 副脚本区显示「暂无副脚本接入」 |
| 面板建在 iframe 回退态 | 标题栏右侧显示小字「frame 内」（现状已有回退逻辑，补可视化） |

## 7. 显示模式（三形态）

| 模式 | 规格 | 说明 |
|------|------|------|
| 标准 | 288px 固定右上 | 现状不变 |
| Ninja | 60px 窄条，悬停展开 | 现状不变；窄条态**新增**显示状态徽章（当前窄条把徽章也藏了，违背"一眼知状态"） |
| 移动 | ≤480px 全宽自适应 | 现状媒体查询保留，按钮点按区 ≥36px |

---

## 8. 可访问性（务实子集）

- 状态徽章与 LED **不单独依赖颜色**：运行/暂停配不同 title 文案（现状已有 title，成文化）；
- 所有可点区域 ≥ 24px（桌面）/ 36px（移动）；
- 命令下拉项键盘可达（现状已支持 ↑↓/Tab/Enter/Esc，保持）；
- 文字对比度：`--text` on `--bg` ≈ 13:1，`--text-2` ≈ 6:1，均过 WCAG AA；`--text-3` 仅用于非关键信息。

## 9. 主题扩展（预留，不做）

令牌化后天然支持第二主题：`STYLES.T = THEMES.dark` 换成 `THEMES.light` 即可。本方案**只交付深色**（面板宿主页面以深色视频页为主，浅色无实际场景），仅保证架构不堵死。

## 10. 工程落地（映射现有架构，分三阶段）

依托已完成的 P0–P4 重构（Store 事件总线、平台适配层均已就绪），UI 改造作为 **P5**：

| 阶段 | 内容 | 风险 | 验证 |
|------|------|------|------|
| **P5a 令牌化** | `meta-config/config.js` 新增 `STYLES.T` 令牌表；`ui/panel-core.js`(`ensurePanel`)/`ui/addons.js`(`renderAddons`) 内联样式中的色值、字号、圆角逐一替换为令牌引用；新增 `window.__cxUI = STYLES` 导出 | 低（纯替换，无结构变化） | 代码行多重集 diff 仅"字面量→令牌引用"差异；冒烟确认面板视觉逐像素一致 |
| **P5b IA 重组** | 4 个 tab 容器重排（DOM 移动 + `switchTab` 映射更新）；`cx_panel_tab` 旧值迁移映射（pause→control, adv→insight, other→system, sub→automation） | 中（DOM 结构变化） | 事件绑定全部委托到重建后元素；冒烟确认各按钮/滑块功能不变、tab 记忆正常 |
| **P5c 组件化 + 反馈分级** | 按钮四级制收口；`toast(msg, level)` 加级别；空态文案；Ninja 窄条显示徽章 | 低 | grep 确认按钮色值仅存于令牌；逐项过 §6.1 反馈矩阵 |

> 每阶段独立交付、独立回滚，产物仍是单文件 `.user.js`，`src/` 目录结构不变（只动 `meta-config/config.js` / `ui/panel-core.js` / `ui/addons.js` 三个文件）。
