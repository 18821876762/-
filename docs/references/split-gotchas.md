# 模块拆分参考

> 核对基线：4.20.3；核对日期：2026-10-14。配套：[架构治理](../ARCHITECTURE_GOVERNANCE.md)。

## 保留语法与作用域边界

JavaScript 在 `return` 后换行会自动插入分号。需要跨行返回表达式时，在同一行打开括号：

```js
// 返回 undefined，下一行的表达式不会成为返回值。
function broken() {
  return
    '<div>内容</div>';
}

// 返回完整字符串。
function correct() {
  return (
    '<div>内容</div>'
  );
}
```

检查时区分合法的 `return;` 和意外的裸 `return` 换行。以下命令用于定位候选，逐处核对语义：

```powershell
rg -n '^\s*return\s*$' apps/userscript/src/
```

同样保留模板字符串、正则、括号、注释及局部变量的边界。不要把原先嵌套函数直接提升到共享 IIFE 顶层：它可能依赖外层参数、局部状态或闭包，移动后还可能与其他模块重名。

## 构建顺序仍然重要

函数声明可以提升；`var` 只提升声明，赋值仍按拼接顺序执行，`let` / `const` 还受初始化前访问限制。调用函数时，其内部依赖的对象或变量必须已经初始化。事件注册和立即执行表达式也不会因函数提升而变得顺序无关。

拆分时核对 [build-manifest.txt](../../apps/userscript/build-manifest.txt)中的顺序、`@provides` / `@requires`、共享变量赋值、公开 API 挂载和清理回调。模板插值变量只在保留原作用域时才能直接沿用。

保留同一个函数或嵌套 IIFE 的片段用相同 `@source-group` 标记，必须在构建清单中连续排列；逻辑入口和后续片段由 [source-groups.cjs](../../apps/userscript/scripts/source-groups.cjs)按清单顺序拼装。抽取测试应读取完整逻辑组，不能把共享闭包局部提升成裸全局来满足单文件扫描。

## 拆分后的验证

1. 核对函数和共享变量没有遗漏、重复定义或作用域变化；明确哪些模块负责初始化、挂载与清理。
2. 更新构建清单和依赖声明。在项目根运行 `scripts/build.ps1`，由构建器检查完整拼接产物。源文件可能是 IIFE 片段，单独语法检查不能代替产物检查。
3. 运行 `scripts/test.ps1`；涉及面板或浏览器交互时补充对应场景，确保被拆分的行为确实覆盖。
4. 运行 `apps/userscript/check-module-size.ps1`，对照拆分前后结果。2026-10-10 的 4.20.2 已完成 14 个超限模块拆分，唯一旧白名单为 dom.js；以后仍须独立运行体积门，构建成功本身不代表体积门通过。
5. 核对公开契约和模块依赖文档；对完整拼接源码比较语法树，明确允许差异。4.20.2 那次拆分只允许 `SCRIPT_VERSION` 显示常量更新，证据见 [历史拆分记录](../../backups/refactor/2026-10-10/module-split/拆分说明.md)；4.20.3 的凭据与异步行为有实质修改，不能直接沿用旧等价结论。结构化符号或语法等价检查无法代替运行回归。

元数据头、结尾和括号外观只能作快速检查。字符串、正则及注释中的符号会干扰简单计数，大括号配平不等于 JavaScript 语法有效。没有可用 Node 时，应先恢复验证环境，不能用计数替代语法与行为验收。

## 自动切片与编码

切片脚本应按明确的语法边界处理，并先保存可恢复的原件。PowerShell 5.1 与新版 PowerShell 对无 BOM UTF-8 的读取方式不同；包含中文的脚本或文件应明确编码，读写后核对内容，避免引号与字符被错误解码。中文注释本身不是语法错误。

现行验证命令和环境入口见[应用说明](../../apps/userscript/README.md)，公开边界见[契约](../CONTRACT.md)。

当前有 108 份源码、106 项清单及两个入口；凭据模块须在使用方执行前初始化，并保持私有闭包边界。当次检查及产物来源见 [4.20.3 发布记录](../releases/4.20.3.md)。
